Before first use, configure OIDC in your identity provider (one-time):

1. Create an OAuth2/OIDC application.
2. Client type: Confidential.
3. Redirect URI: {{ .Values.auth.url }}/api/auth/callback/oidc
4. Scopes: openid, email, profile.
5. Note the issuer URL, client ID, and client secret.
6. Store the secrets under these exact key names. The web pods load each Secret
   whole, as environment variables, so a key with any other name isn't read:
     Secret {{ .Values.auth.oidc.clientSecretRef.name }}, key OIDC_CLIENT_SECRET = <client secret>
     Secret {{ .Values.auth.sessionSecretRef.name }}, key AUTH_SECRET = <output of: openssl rand -hex 32>

Migrations apply when a pod starts, before it serves traffic. Watch a rollout:
  kubectl -n {{ .Release.Namespace }} logs -l app.kubernetes.io/instance={{ .Release.Name }} --prefix --tail=-1 | grep '\[startup\]'

To upload scans, sign in from a repository with the CLI installed, then scan:
  yarn scout auth login --host {{ .Values.auth.url }}
  yarn scout scan --host {{ .Values.auth.url }}
