A React component's `propTypes` and `defaultProps`, assigned at module level or as `static` fields of a class, are now read as its declared props. Its props are the names it destructures plus the keys of `propTypes`, so a component that takes `props` without destructuring now has declared props too. `.isRequired` marks a prop required, and a `defaultProps` value is its default when the destructure doesn't set one, written the same way as other defaults (`default`, or `hasDefault` and `defaultRef`). A prop that a fully read `defaultProps` doesn't name has `hasDefault: false`. When `defaultProps` can't be read in full, such as an imported object or a spread, the props it could set are left unread. React 19 ignores `defaultProps` on function components, so when React 19 or later is installed their `defaultProps` give `hasDefault: false`, and when the scan can't find the React version, the props `defaultProps` names are left unread. Class components keep their defaults. In JavaScript repos that use `propTypes`, more components have declared props, and the unused-props counts change to match.
